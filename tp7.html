    2. Du texte au DataFrame : le schéma

    Au TP5, chaque ligne était une chaîne de caractères que vous découpiez vous-mêmes (l.split("\t"), puis c[2], float(c[4])). Un DataFrame, lui, connaît ses colonnes et leurs types : c'est le schéma.

    3.2 En SQL

    On donne d'abord un nom au DataFrame (une vue temporaire), puis on l'interroge en SQL :

    3.3 En RDD, pour comparer

    Reprenez le code du TP5 (sections 7.3 et 7.4) dans le même shell :

    big = sc.textFile("hdfs:///input/purchases_big.txt")
ca_rdd = (big.map(lambda l: l.split("\t"))
             .map(lambda c: (c[2], float(c[4])))
             .reduceByKey(lambda a, b: a + b))
ca_rdd.takeOrdered(5, key=lambda t: -t[1])

    3.4 Vérifier que les trois résultats sont identiques

    Comparer à l'œil 19 villes est fastidieux. On transforme le RDD en DataFrame, puis on cherche les lignes qui diffèrent avec exceptAll (une différence d'ensembles) :

    rdd_df = spark.createDataFrame(ca_rdd, ["ville", "ca"])
arrondi = lambda df: df.select("ville", F.round("ca", 2).alias("ca"))

arrondi(ca_df).exceptAll(arrondi(rdd_df)).count()     # 0 : aucune différence
arrondi(ca_sql).exceptAll(arrondi(ca_df)).count()     # 0
    Pourquoi arrondir ? Une somme de nombres décimaux (double) peut différer au-delà de la dixième décimale selon l'ordre dans lequel les additions sont faites, et cet ordre dépend du plan d'exécution. Pour un montant en francs CFA ou en dollars, deux décimales suffisent.

    4. Ce que fait Catalyst

    4.1 Lire un plan physique

    ca_df.explain("formatted")
ca_sql.explain("formatted")

    Un plan se lit de bas en haut. Pour le CA par ville, vous devez retrouver :

    Étape du planRôle
    Scan csv — ReadSchemalecture du fichier ; seules les colonnes utiles sont décodées
    HashAggregate — partial_sumsomme partielle, dans chaque partition, avant le shuffle
    Exchange hashpartitioning(ville, 200)le shuffle : regroupe les sommes partielles d'une même ville
    HashAggregate — sumsomme finale par ville
    Exchange rangepartitioning puis Sortle tri du ORDER BY : un second shuffle
    Lecture ingénieur : Tungsten et le whole-stage codegen. Dans explain() (mode simple), les opérateurs préfixés par *(1), *(2)… sont fusionnés en une seule fonction Java générée à l'exécution : une boucle sur les lignes, sans appel virtuel ni objet intermédiaire par ligne. Le même plan est visible par ca_df.explain("codegen"). Un Exchange brise toujours la chaîne : c'est une frontière de stage. Les lambdas Python du TP5, elles, ne peuvent pas être fusionnées : chaque ligne traverse la frontière JVM ↔ Python.

    Si la requête a déjà été exécutée, explain affiche deux plans : Final Plan (ajusté pendant l'exécution, avec des nœuds AQEShuffleRead, voir section 4.3) et Initial Plan. Lisez l'Initial Plan.

    5. Du texte au format Parquet

    Le fichier texte du TP5 est lu en entier à chaque requête, ligne par ligne. Parquet est un format en colonnes, compressé et typé : Spark n'y lit que les colonnes, et parfois que les morceaux de fichier, dont il a besoin.

    5.1 Écrire en Parquet, partitionné par ville

    7. Les fonctions de fenêtre

    Un groupBy réduit : une ligne par groupe. Une fonction de fenêtre garde toutes les lignes et ajoute un calcul fait sur le groupe : un rang, une part, un cumul. C'est l'outil des classements (« top N par région ») et des parts de marché.

    from pyspark.sql import Window

ca_ville_region = (ventes.join(regions, "ville")
                         .groupBy("region", "ville")
                         .agg(F.round(F.sum("montant"), 2).alias("ca")))

par_region = Window.partitionBy("region").orderBy(F.desc("ca"))
(ca_ville_region.withColumn("rang", F.rank().over(par_region))
                .filter("rang <= 2")
                .orderBy("region", "rang")
                .show())

    La même requête en SQL :

    ca_ville_region.createOrReplaceTempView("ca_ville_region")
spark.sql("""
    SELECT * FROM (
        SELECT region, ville, ca,
               RANK() OVER (PARTITION BY region ORDER BY ca DESC) AS rang
        FROM ca_ville_region)
    WHERE rang <= 2
    ORDER BY region, rang
""").show()

    9. Une application DataFrame avec spark-submit

    Voici l'équivalent DataFrame du script ca_par_ville.py du TP5 (section 9). Créez ~/ca_par_ville_df.py :

    nano ~/ca_par_ville_df.py

    #!/usr/bin/env python3
"""TP7 — Chiffre d'affaires par ville en DataFrame, soumis à YARN avec spark-submit."""
import sys

from pyspark.sql import SparkSession, functions as F
from pyspark.sql.types import StructType, StructField, StringType, DoubleType

entree, sortie = sys.argv[1], sys.argv[2]
spark = SparkSession.builder.appName("TP7 - CA par ville (DataFrame)").getOrCreate()
spark.sparkContext.setLogLevel("WARN")

schema = StructType([StructField(nom, DoubleType() if nom == "montant" else StringType())
                     for nom in ["date", "heure", "ville", "categorie", "montant", "paiement"]])

ca = (spark.read.csv(entree, sep="\t", schema=schema)
           .groupBy("ville")
           .agg(F.round(F.sum("montant"), 2).alias("ca"))
           .orderBy(F.desc("ca")))

ca.write.mode("overwrite").csv(sortie, header=True)

print("Top 5 des villes par chiffre d'affaires :")
ca.show(5)
spark.stop()
    spark-submit --deploy-mode client ~/ca_par_ville_df.py \
    hdfs:///input/purchases_big.txt hdfs:///output-spark-ca-df

hdfs dfs -ls /output-spark-ca-df
hdfs dfs -cat /output-spark-ca-df/part-* | head -5
