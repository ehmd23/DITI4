Sommaire

    Introduction

    Du TP1 au TP7, vous avez construit votre plateforme : installer Java, Hadoop et Spark, régler la mémoire de YARN, protéger /tmp, ouvrir des tunnels SSH. Databricks propose l'inverse : la plateforme est déjà là, dans le navigateur, et le calcul démarre en quelques secondes. Ce TP refait le travail du TP7 sur Databricks Free Edition, l'offre gratuite destinée à l'apprentissage.

    Objectif du TP : créer un espace Databricks, y ranger les données dans Unity Catalog, rejouer le TP7 dans un notebook serverless, découvrir ce que la plateforme interdit et ce qu'elle ajoute (Delta Lake, tableau de bord, job planifié), puis comparer les quatre derniers TP.

    1. Prérequis

    • Le TP7 terminé : vous réutiliserez votre code DataFrame et SQL, et vos mesures.
    • Un navigateur récent et une adresse e-mail (de préférence celle de l'école). Aucune carte bancaire n'est demandée.
    • Le fichier regions.csv du TP7 (section 6) sur votre poste. Récupérez-le depuis la VM, dans un terminal de votre poste : scp hadoop@IP_DE_LA_VM:~/regions.csv . — ou recréez-le avec un éditeur de texte.
    • Le notebook du TP : tp8_etudiant.ipynb (clic droit → Enregistrer le lien sous… si le navigateur l'affiche au lieu de le télécharger).
    Free Edition : des limites à connaître. Uniquement du calcul serverless, un seul SQL warehouse de taille 2X-Small, au plus 5 tâches de job simultanées, et un quota quotidien : s'il est dépassé, le calcul est coupé jusqu'au lendemain (les données sont conservées). L'offre est réservée à un usage non commercial. Travaillez sobrement : pas de boucle de mesures inutiles, et mettez en pause le job à la fin.

    L'interface de Databricks évolue souvent : si un libellé diffère légèrement de ce qui est écrit ici, cherchez l'élément équivalent au même endroit.

    2. Créer son espace Databricks

    2.1 Inscription

    1. Ouvrez la page d'inscription de Databricks Free Edition : https://login.databricks.com/?intent=CE_SIGN_UP.
    2. Choisissez une méthode : compte Google, compte Microsoft, ou adresse e-mail (un code à usage unique vous est alors envoyé).
    3. Databricks crée votre espace de travail (workspace). Patientez jusqu'à l'affichage de la page d'accueil.

    La barre latérale gauche regroupe les outils. Repérez ceux dont vous aurez besoin :

    Cliquez sur Catalog : un catalogue nommé workspace doit apparaître, avec un schéma default. C'est ce catalogue que le TP utilise. S'il porte un autre nom dans votre espace, notez-le : vous l'indiquerez dans le notebook.

    Unity Catalog en une phrase : tout objet de données a un nom en trois parties, catalogue.schéma.objet (par exemple workspace.tp8.ventes), et des droits d'accès gérés au même endroit. C'est le rôle que jouait le metastore de Hive au TP4, étendu aux fichiers.

    3.4 Générer 3 millions de ventes avec Spark

    Pas de VM, donc pas de python3 gen_ventes.py. La partie 3 du notebook produit le même genre de données avec Spark : spark.range crée 3 millions de lignes numérotées, puis chaque colonne est tirée au hasard. Les montants ne seront donc pas ceux du TP7 : comparez les démarches, les plans et les temps, pas les chiffres.

    gen = (spark.range(1, 3_000_001).withColumnRenamed("id", "id_vente")
       .select("id_vente",
               F.format_string("2012-%02d-%02d", entier(1, 12, 1), entier(1, 28, 2)).alias("date"),
               # … heure, ville, catégorie, montant, paiement
       ))
gen.drop("id_vente").write.mode("overwrite").csv(f"{BASE}/purchases_big", sep="\t")

    4.1 Lire et calculer

    La partie 4 du notebook relit les données avec le schéma du TP7, puis calcule le CA par ville en DataFrame et en SQL. Seuls les chemins changent :

    ventes = spark.read.csv(f"{BASE}/purchases_big", sep="\t", schema=schema)   # TP7 : hdfs:///input/purchases_big.txt
ventes.createOrReplaceTempView("ventes")
    %sql
SELECT ville, ROUND(SUM(montant), 2) AS ca
FROM ventes
GROUP BY ville
ORDER BY ca DESC

    6. Delta Lake : une table que l'on peut corriger

    Au TP7, un dossier Parquet ne se modifiait pas : pour corriger deux ventes, il fallait réécrire les fichiers. Une table Delta (le format par défaut de Databricks) ajoute aux fichiers Parquet un journal de transactions : les mises à jour deviennent possibles, atomiques et historisées.

    6.1 Créer la table

    gen.write.mode("overwrite").saveAsTable(f"{CATALOGUE}.{SCHEMA}.ventes")
    %sql
DESCRIBE DETAIL workspace.tp8.ventes

    Dans Catalog, ouvrez la table ventes : parcourez les onglets Overview (colonnes), Sample Data et History.

    6.2 Intégrer des corrections

    Cas réel de correction de données : une source amont signale deux ventes saisies sans la remise de 10 %, et une vente oubliée. Le notebook prépare une vue corrections (deux lignes modifiées, une nouvelle), puis les intègre en une seule opération :

    %sql
MERGE INTO workspace.tp8.ventes AS t
USING corrections AS c
ON t.id_vente = c.id_vente
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *

    6.3 L'historique et le voyage dans le temps

    %sql
DESCRIBE HISTORY workspace.tp8.ventes;

SELECT id_vente, montant
FROM workspace.tp8.ventes VERSION AS OF 0
WHERE id_vente IN (1, 2, 3000001)

    Remplacez 0 par le numéro de version qui précède le MERGE, lu dans la colonne version de l'historique. Complétez enfin la cellule # À FAIRE : l'écart de CA total entre la version d'avant le MERGE et la version actuelle.

    Question 4 : d'après DESCRIBE DETAIL, quel est le format de la table, combien de fichiers la composent ? Quelles opérations l'historique contient-il, et que dit-il du MERGE (lignes modifiées, insérées) ? Quel écart de CA trouvez-vous ? Quelles garanties le journal de transactions apporte-t-il (atomicité, isolation, reproductibilité d'un résultat passé grâce au time travel) ?     8. Un traitement planifié chaque nuit

    Le tableau de bord doit être à jour chaque matin, quelles que soient les corrections intégrées dans la journée. On planifie donc le recalcul de ca_region_mois.

    8.1 Le notebook du job

    1. Dans Workspace → Home, créez un notebook (Create → Notebook) nommé tp8_job.
    2. Écrivez-y une cellule qui recrée workspace.tp8.ca_region_mois à partir de ventes et regions (la requête de la section 7.1) et qui affiche le nombre de lignes produites.
    3. Exécutez-le une fois à la main pour le vérifier.

    8.2 Créer et planifier le job

    1. Ouvrez Jobs & Pipelines, puis Create → Job.
    2. Nommez le job TP8 - CA par région (nuit). Pour la première tâche : Type Notebook, Path votre notebook tp8_job, Compute Serverless. Cliquez sur Create task.
    3. Dans le panneau de droite, Schedules & Triggers → Add trigger → type Scheduled : tous les jours à 6 h 00, fuseau horaire Africa/Dakar (UTC). Enregistrez.
    4. Cliquez sur Run now, puis ouvrez l'onglet Runs pour suivre l'exécution et lire sa sortie.
    5. Une fois l'exécution réussie, mettez la planification en pause (Pause) pour préserver votre quota.
    Question 6 : comparez ce job avec ce qu'il aurait fallu faire au TP5 ou au TP6 pour obtenir le même résultat (spark-submit, planificateur du système, journaux, relance en cas d'échec). Que vous apporte l'onglet Runs ? Que se passe-t-il pour le tableau de bord si l'exécution de la nuit échoue ?
