Installer Apache Hadoop en mode pseudo-distribué

Installer HDFS, YARN et MapReduce sur une seule machine, puis valider l'installation par un premier job.

DITI 4Diplôme d'Ingénieur en Techniques InformatiquesAnnée 2026-2027Hadoop 3.5.0Java 21Ubuntu Server 26.04 LTSOctobre 2026

Objectif

Un cluster complet sur une seule machine : les cinq démons Hadoop tournent chacun dans sa JVM.

Lien avec le cours

Chapitre 3 — HDFS et YARN : NameNode, DataNode, ResourceManager, NodeManager.

Enjeu d'ingénieur

Disposer d'un laboratoire reproductible : valider une configuration sur un poste avant de la déployer sur un cluster.

Sommaire

    Introduction

    Apache Hadoop est un framework open-source conçu pour le stockage et le traitement distribué de grands ensembles de données (Big Data) sur des clusters de machines standard. Il repose sur quatre modules principaux :

    • Hadoop Common : Les utilitaires communs supportant les autres modules.
    • HDFS (Hadoop Distributed File System) : Un système de fichiers distribué offrant un accès haut débit aux données applicatives.
    • Hadoop YARN : Un framework pour la planification des tâches et la gestion des ressources du cluster.
    • Hadoop MapReduce : Un système basé sur YARN pour le traitement parallèle de grands ensembles de données.
    Objectif du TP : Ce guide détaille l'installation pas à pas d'Apache Hadoop version 3.5.0 sur le système d'exploitation Ubuntu Server 26.04 LTS. Nous utiliserons le Mode Pseudo-Distribué.

    Note sur le mode Pseudo-Distribué : Dans ce mode, tous les démons Hadoop (NameNode, SecondaryNameNode, DataNode, ResourceManager, NodeManager) s'exécutent sur une seule machine (votre ordinateur), chacun dans un processus Java distinct. Cela simule un cluster complet et est idéal pour l'apprentissage, le développement et le test.

    1. Prérequis

    1.1 Configuration matérielle recommandée

    Composant Configuration Minimale Recommandée
    Système d'exploitation Ubuntu Server 26.04 LTS (64-bit) Ubuntu Server 26.04 LTS (64-bit)
    Mémoire RAM 4 Go 8 Go ou plus
    Espace Disque 20 Go libres 50 Go libres (SSD recommandé)
    Privilèges Accès root (sudo) Accès root (sudo)

    1.2 Mise à jour du système

    Avant de commencer, assurez-vous que votre système est à jour :

    sudo apt update

    2. Installation de Java OpenJDK 21

    Nous utiliserons OpenJDK 21 Java 21, la même version pour l'ensemble des TP (TP1 à TP3). 

    sudo apt install openjdk-21-jdk -y
    Ubuntu Server 26.04 : le JDK par défaut de cette version est Java 25 (paquet default-jdk). N'installez donc pas default-jdk : demandez explicitement openjdk-21-jdk, comme ci-dessus. Ce paquet est dans le dépôt universe, activé par défaut sur Ubuntu Server.
    Java et Hadoop 3.5.0 : la documentation officielle de Hadoop 3.5.0 indique que les démons (côté serveur) requièrent Java 17, Java 21 n'étant officiellement supporté que côté client. Le module utilise Java 21, avec lequel Hadoop 3.5.0 a été testé pour ces TP. En cas de comportement anormal d'un démon, passez à Java 17 en suivant la section 10 : Hadoop et ses données sont conservés, rien n'est à réinstaller.

    Vérifiez l'installation :

    java -version

    Résultat attendu (similaire à) : openjdk version "21.0.x" ...

    Identifiez le chemin d'installation de Java pour la configuration future :

    which java
readlink -f $(which java)

    Le chemin devrait ressembler à : /usr/lib/jvm/java-21-openjdk-amd64/bin/java.
    Le JAVA_HOME sera donc : /usr/lib/jvm/java-21-openjdk-amd64.

    3. Configuration SSH et utilisateur Hadoop

    Hadoop nécessite SSH pour gérer ses nœuds, même en mode pseudo-distribué.

    3.1 Installation SSH et pdsh

    sudo apt install openssh-server openssh-client pdsh -y

    3.2 Création de l'utilisateur hadoop

    Il est recommandé de créer un utilisateur système dédié pour isoler l'installation Hadoop.

    sudo adduser --disabled-password --comment "" hadoop
sudo usermod -aG sudo hadoop
sudo passwd hadoop
# Entrez un mot de passe simple (ex: hadoop) pour le TP

    Connectez-vous avec ce nouvel utilisateur :

    su - hadoop

    3.3 Configuration SSH sans mot de passe

    Hadoop doit pouvoir se connecter à localhost sans intervention humaine.

    # Générer une paire de clés RSA (laissez la passphrase vide en appuyant sur Entrée)
ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa

# Autoriser la clé publique
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
chmod 0600 ~/.ssh/authorized_keys

# Tester la connexion
ssh localhost
    Important : Lors de la première connexion ssh localhost, tapez "yes" pour accepter l'empreinte. Si vous êtes connecté sans demande de mot de passe, la configuration est réussie. Tapez exit pour revenir au shell normal si nécessaire.

    4. Téléchargement et installation de Hadoop 3.5.0

    Nous allons télécharger la version binaire stable depuis les miroirs Apache.

    # Téléchargement
wget https://archive.apache.org/dist/hadoop/common/hadoop-3.5.0/hadoop-3.5.0.tar.gz

# Extraction
tar -xvzf hadoop-3.5.0.tar.gz

# Déplacement vers /opt 
sudo mv hadoop-3.5.0 /opt/hadoop

# Attribution des droits à l'utilisateur hadoop
sudo chown -R hadoop:hadoop /opt/hadoop

    Vérification rapide :

    ls -l /opt/hadoop

    5. Configuration des variables d'environnement

    Il faut configurer le shell pour qu'il trouve les commandes Hadoop et Java.

    Éditez le fichier .bashrc de l'utilisateur hadoop :

    nano ~/.bashrc

    Ajoutez les lignes suivantes à la fin du fichier :

    # ---- Hadoop Environment Variables ----
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export HADOOP_HOME=/opt/hadoop
export HADOOP_INSTALL=$HADOOP_HOME
export HADOOP_MAPRED_HOME=$HADOOP_HOME
export HADOOP_COMMON_HOME=$HADOOP_HOME
export HADOOP_HDFS_HOME=$HADOOP_HOME
export HADOOP_YARN_HOME=$HADOOP_HOME
export HADOOP_COMMON_LIB_NATIVE_DIR=$HADOOP_HOME/lib/native
export PATH=$PATH:$HADOOP_HOME/sbin:$HADOOP_HOME/bin
export HADOOP_OPTS="-Djava.library.path=$HADOOP_HOME/lib/native"

    Sauvegardez (Ctrl+O, Entrée) et quittez (Ctrl+X). Appliquez les changements :

    source ~/.bashrc

    Testez si Hadoop est reconnu :

    hadoop version

    Vous devriez voir : Hadoop 3.5.0

    Enfin, éditez le fichier de configuration interne hadoop-env.sh pour forcer le chemin Java :

    nano $HADOOP_HOME/etc/hadoop/hadoop-env.sh

    Trouvez la ligne export JAVA_HOME=... (souvent commentée) et remplacez-la par :

    export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64

    6. Configuration du cluster Hadoop (Mode Pseudo-Distribué)

    Nous devons modifier 4 fichiers XML situés dans $HADOOP_HOME/etc/hadoop/.

    6.1 Création des répertoires de données HDFS

    sudo mkdir -p /home/hadoop/hdfs/namenode
sudo mkdir -p /home/hadoop/hdfs/datanode
sudo mkdir -p /home/hadoop/hadoop-tmp
sudo chown -R hadoop:hadoop /home/hadoop/hdfs/ /home/hadoop/hadoop-tmp

    6.2 Fichier core-site.xml

    Configure l'adresse du NameNode (le maître du système de fichiers) et le dossier des fichiers de travail de Hadoop. Sur Ubuntu Server 26.04, /tmp est en mémoire vive (tmpfs) : petit et vidé à chaque redémarrage. On place donc ces fichiers sur le disque, dans /home/hadoop/hadoop-tmp.

    nano $HADOOP_HOME/etc/hadoop/core-site.xml

    <configuration>
    <property>
        <name>fs.defaultFS</name>
        <value>hdfs://localhost:8020</value>
    </property>
    <property>
        <name>hadoop.tmp.dir</name>
        <value>/home/hadoop/hadoop-tmp</value>
    </property>
</configuration>

    6.3 Fichier hdfs-site.xml

    Configure la réplication (1 seule copie car 1 seul nœud) et les chemins de stockage.

    nano $HADOOP_HOME/etc/hadoop/hdfs-site.xml

    <configuration>
    <property>
        <name>dfs.replication</name>
        <value>1</value>
    </property>
    <property>
        <name>dfs.namenode.name.dir</name>
        <value>file:///home/hadoop/hdfs/namenode</value>
    </property>
    <property>
        <name>dfs.datanode.data.dir</name>
        <value>file:///home/hadoop/hdfs/datanode</value>
    </property>
    <property>
      <name>dfs.namenode.rpc-bind-host</name>
      <value>0.0.0.0</value>
    </property>
    <property>
      <name>dfs.namenode.http-bind-host</name>
      <value>0.0.0.0</value>
    </property>
    <property>
      <name>dfs.datanode.address</name>
      <value>0.0.0.0:9866</value>
    </property>
    <property>
      <name>dfs.namenode.datanode.registration.ip-hostname-check</name>
      <value>false</value>
    </property>
</configuration>

    La taille de bloc n'est pas modifiée : on garde la valeur par défaut de 128 Mo, celle étudiée au chapitre 3 du cours.

    6.4 Fichier mapred-site.xml

    Indique à MapReduce d'utiliser YARN comme gestionnaire de ressources.

    nano $HADOOP_HOME/etc/hadoop/mapred-site.xml

    <configuration>
      <property>
      <name>mapreduce.framework.name</name>
      <value>yarn</value>
    </property>
    <property>
      <name>mapreduce.application.classpath</name>
      <value>$HADOOP_MAPRED_HOME/share/hadoop/mapreduce/*:$HADOOP_MAPRED_HOME/share/hadoop/mapreduce/lib/*</value>
    </property>
</configuration>

    6.5 Fichier yarn-site.xml

    Active le service de shuffle nécessaire pour MapReduce.

    nano $HADOOP_HOME/etc/hadoop/yarn-site.xml

    <configuration>
      <property>
      <name>yarn.resourcemanager.hostname</name>
      <value>localhost</value>
    </property>
    <property>
      <name>yarn.resourcemanager.bind-host</name>
      <value>0.0.0.0</value>
    </property>
    <property>
      <name>yarn.nodemanager.aux-services</name>
      <value>mapreduce_shuffle</value>
    </property>
    <property>
      <name>yarn.nodemanager.aux-services.mapreduce_shuffle.class</name>
      <value>org.apache.hadoop.mapred.ShuffleHandler</value>
    </property>
    <property>
      <name>yarn.nodemanager.resource.memory-mb</name>
      <value>4096</value>
    </property>
    <property>
      <name>yarn.nodemanager.env-whitelist</name>
      <value>JAVA_HOME,HADOOP_COMMON_HOME,HADOOP_HDFS_HOME,HADOOP_CONF_DIR,CLASSPATH_PREPEND_DISTCACHE,HADOOP_YARN_HOME,HADOOP_HOME,PATH,LANG,TZ,HADOOP_MAPRED_HOME</value>
    </property>
</configuration>
    Mémoire YARN : yarn.nodemanager.resource.memory-mb = 4096 convient à une machine de 8 Go. Si votre machine n'a que 4 Go de RAM, indiquez 2048.

    7. Initialisation et démarrage du cluster

    7.1 Formatage du NameNode

    Cette étape initialise le système de fichiers HDFS. Elle ne doit être faite qu'une seule fois.

    hdfs namenode -format
    ATTENTION : Ne formatez le NameNode qu'une seule fois lors de l'installation ! Si vous reformatez un NameNode en cours d'utilisation, vous perdrez toutes les données stockées dans HDFS et casserez la synchronisation avec les DataNodes.

    7.2 Démarrage des services

    Avant de démarrer, définissons le type de connexion RCMD pour éviter une erreur courante avec pdsh :

    export PDSH_RCMD_TYPE=ssh

    Pour ne pas avoir à la retaper à chaque session, ajoutez aussi cette ligne à la fin de ~/.bashrc.

    Vous pouvez démarrer tous les services (HDFS + YARN) en une seule commande :

    start-all.sh

    Ou séparément :

    start-dfs.sh
start-yarn.sh

    7.3 Arrêt des services

    Pour arrêter proprement le cluster à la fin du TP :

    stop-all.sh

    8. Vérification et validation

    8.1 Vérification des processus Java actifs

    Utilisez l'outil jps (Java Process Status) pour vérifier que tous les démons tournent.

    jps

    Vous devez voir ces 5 démons Hadoop, plus Jps lui-même (les numéros PID seront différents) :

    Nom du Processus Rôle
    NameNode Maître HDFS (Gestion des métadonnées)
    DataNode Travailleur HDFS (stockage des blocs de données)
    ResourceManager Maître YARN (Gestion globale des ressources)
    NodeManager Travailleur YARN (exécution des conteneurs)
    SecondaryNameNode Maintenance des métadonnées (Checkpoints)
    Jps L'outil de vérification lui-même

    8.2 Interfaces Web de supervision

    Ouvrez votre navigateur (Firefox/Chrome) aux adresses suivantes :

    • HDFS NameNode UI : http://localhost:9870 (Vue d'ensemble du stockage)
    • YARN ResourceManager UI : http://localhost:8088 (Vue des jobs en cours)
    • HDFS DataNode UI : http://localhost:9864
    Lecture ingénieur : chaque démon est une JVM distincte ; les cinq cohabitent sur la même machine et se partagent sa mémoire. Le NameNode conserve l'espace de noms en mémoire et le persiste sur disque (fsimage et journal edits, dans dfs.namenode.name.dir) ; les DataNodes ne stockent que les blocs.

    8.3 Tests fonctionnels HDFS

    Testons l'écriture et la lecture sur le système de fichiers distribué.

    # 1. Créer des répertoires utilisateurs dans HDFS
hdfs dfs -mkdir -p /user/hadoop
hdfs dfs -mkdir /test_input

# 2. Copier un fichier local (ex: logs système) vers HDFS
hdfs dfs -put /var/log/syslog /test_input/

# 3. Lister le contenu du répertoire HDFS
hdfs dfs -ls /test_input/

# 4. Lire le début du fichier depuis HDFS
hdfs dfs -cat /test_input/syslog | head -5

    8.4 Exécution d'un job MapReduce d'exemple (Grep)

    Nous allons lancer un programme d'exemple (Grep) qui compte les occurrences d'un motif.

    # Préparation : Copier les fichiers XML de config comme données d'entrée
hdfs dfs -mkdir input
hdfs dfs -put $HADOOP_HOME/etc/hadoop/*.xml input

# Exécution du job MapReduce
hadoop jar $HADOOP_HOME/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.5.0.jar grep input output 'dfs[a-z.]+'

# Affichage des résultats
hdfs dfs -cat output/*
    Si vous voyez une liste de propriétés commençant par "dfs..." avec un nombre à côté, félicitations ! Votre cluster Hadoop est fonctionnel et capable d'exécuter des traitements MapReduce.

    9. Résolution des problèmes courants (Dépannage)

    Symptôme Cause probable Solution
    Connection refused sur localhost:8020 NameNode n'est pas démarré Vérifiez les logs dans $HADOOP_HOME/logs/. Avez-vous formaté le NameNode ?
    NameNode est en safe mode Protection automatique au démarrage Attendre que les DataNodes envoient leurs rapports de blocs (quelques secondes). Ne forcer la sortie (hdfs dfsadmin -safemode leave) qu'après avoir vérifié hdfs dfsadmin -report.
    Permission denied lors du start-all.sh PDSH tente d'utiliser rsh au lieu de ssh Exécutez : export PDSH_RCMD_TYPE=ssh
    SSH demande un mot de passe Clés SSH mal configurées ou droits incorrects Vérifiez les droits : chmod 600 ~/.ssh/authorized_keys et chmod 700 ~/.ssh
    DataNode absent dans JPS Incompatibilité ClusterID après reformatage Supprimez les données : rm -rf /home/hadoop/hdfs/datanode/* et redémarrez.

    10. Passer à Java 17 (si nécessaire)

    Cette section sert si un démon se comporte mal sous Java 21, ou si l'on veut s'en tenir à la configuration officielle de Hadoop 3.5.0 (Java 17 côté serveur). Les deux JDK peuvent cohabiter sur la machine : on installe Java 17, puis on indique à Hadoop de l'utiliser. Ni Hadoop ni les données HDFS ne sont touchés : pas de réinstallation, pas de nouveau formatage du NameNode.

    10.1 Arrêter le cluster

    Toujours avec l'utilisateur hadoop :

    stop-all.sh
jps

    Seul Jps doit rester affiché.

    10.2 Installer OpenJDK 17

    sudo apt update
sudo apt install openjdk-17-jdk -y

# Les deux JDK sont maintenant présents
ls /usr/lib/jvm/

    Résultat attendu (similaire à) : java-1.17.0-openjdk-amd64 java-17-openjdk-amd64 java-1.21.0-openjdk-amd64 java-21-openjdk-amd64

    Processeur ARM : sur une VM ARM (par exemple sur un Mac Apple Silicon), le dossier se termine par -arm64 au lieu de -amd64. Utilisez dans toute la suite le nom exact affiché par ls /usr/lib/jvm/.

    10.3 Choisir Java 17 par défaut

    Ubuntu gère plusieurs versions de Java avec les « alternatives ». Choisissez Java 17 pour les commandes java et javac :

    sudo update-alternatives --config java
sudo update-alternatives --config javac

    Chaque commande affiche une liste numérotée : tapez le numéro de la ligne qui contient java-17-openjdk, puis Entrée. Vérifiez :

    java -version

    Résultat attendu (similaire à) : openjdk version "17.0.x" ...

    10.4 Mettre à jour JAVA_HOME

    Le chemin de Java est écrit à deux endroits depuis la section 5 : ~/.bashrc et hadoop-env.sh. Remplacez-le dans les deux fichiers en une commande :

    sed -i 's#java-21-openjdk-amd64#java-17-openjdk-amd64#' ~/.bashrc $HADOOP_HOME/etc/hadoop/hadoop-env.sh

# Vérification
grep -n openjdk ~/.bashrc $HADOOP_HOME/etc/hadoop/hadoop-env.sh
source ~/.bashrc
echo $JAVA_HOME

    Les deux fichiers et la variable doivent indiquer /usr/lib/jvm/java-17-openjdk-amd64.

    Pourquoi les deux fichiers ? ~/.bashrc sert à votre terminal (commandes hadoop, hdfs…) ; hadoop-env.sh sert aux démons lancés par start-all.sh via SSH, qui ne lisent pas toujours votre .bashrc. Si l'un des deux reste en Java 21, les démons et vos commandes n'utiliseront pas la même version.

    10.5 Redémarrer et vérifier

    start-all.sh
jps

# Quel Java utilisent les démons ? (un compte par JDK)
ps -eo args | grep -o '/usr/lib/jvm/[^/]*' | sort | uniq -c

    Résultat attendu : les 5 démons dans jps, et une seule ligne 5 /usr/lib/jvm/java-17-openjdk-amd64.

    Relancez enfin le job d'exemple de la section 8.4 (en supprimant d'abord l'ancienne sortie) :

    hdfs dfs -rm -r output
hadoop jar $HADOOP_HOME/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.5.0.jar grep input output 'dfs[a-z.]+'
hdfs dfs -cat output/*
    Si le job affiche le même résultat qu'avant, le passage à Java 17 est terminé : vos données HDFS sont intactes.
    Et pour les autres TP ?
    • TP2 et TP3 : refaites les sections 10.1 à 10.5 sur chaque nœud (master et workers) : tous doivent utiliser le même Java. Le projet Maven compile pour Java 17 (maven.compiler.release = 17) et fonctionne donc sans changement.
    • TP5 (Spark) : rien à faire, Spark 4.2 utilise le JAVA_HOME défini ici et accepte Java 17 comme Java 21.
    • Revenir à Java 21 : même procédure en sens inverse (update-alternatives, puis sed en échangeant 17 et 21).

    Annexe C — Résumé des commandes HDFS les plus utiles

    Commande HDFS Description
    hdfs dfs -ls /chemin Lister le contenu d'un répertoire HDFS
    hdfs dfs -mkdir /chemin Créer un répertoire dans HDFS
    hdfs dfs -put fichier_local /chemin_hdfs Copier un fichier local vers HDFS
    hdfs dfs -get /chemin_hdfs fichier_local Télécharger un fichier de HDFS vers le local
    hdfs dfs -cat /chemin/fichier Afficher le contenu d'un fichier HDFS
    hdfs dfs -rm -r /chemin Supprimer un fichier ou répertoire HDFS
    hdfs dfs -du -s /chemin Afficher la taille d'un répertoire HDFS
    hdfs dfsadmin -report Rapport complet sur l'état du cluster HDFS
    hdfs dfsadmin -safemode leave Forcer la sortie du mode sans échec (uniquement après diagnostic)
    hdfs namenode -format Formater le NameNode (⚠️ efface toutes les données)
